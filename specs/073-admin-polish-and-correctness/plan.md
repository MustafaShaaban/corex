# Spec 073 — Plan

**Branch:** `spec/073-admin-polish-and-correctness` · **Approach:** reuse existing seams; no new subsystems.

## Technical approach (as built)

### FR-001 — Add-ons state filter
- Bucketing lives in the service, not the screen: `AddonCatalogService::filter(array $views, string $filter)`
  and `counts(array $views)`. Buckets key on `AddonView::status() === AddonStatus::Active` (the same
  resolution that prints the badge), so *Active* filtering and the *Active* badge can never disagree. An
  unknown filter returns everything (`default => true`) rather than hiding the catalog.
- `AddonsScreen::currentFilter()` reads `$_GET['tab']` — `sanitize_key(wp_unslash())` then validated against
  the known-filter allowlist, falling back to `FILTER_ALL`. Read-only view selection, so no nonce (documented
  `phpcs:ignore`). `tab` (not `filter`) reuses the query arg `AdminPage::tabs()` already emits.
- `AddonsScreen::filterTabs()` renders through the shared `AdminPage::tabs()` strip; each label carries its
  count via a translated `%1$s (%2$d)` string with a translator comment. Distinct empty-view vs no-add-ons
  states via `AdminPage::state()`.

### FR-002 — Data Models SVG loss
- `DataModelsScreen::render()` drops the `wp_kses_post()` wrapper around `AdminPage::open()/close()/
  permissionDenied()`. Those methods escape every dynamic value at interpolation and their header/rail
  contributors escape their own inline-SVG content, so the return value is trusted chrome; `wp_kses_post()`
  stripped the `<svg>` tags it does not allow. Matches how every other CoreX screen echoes the shell.

### FR-003 — Operations & Security single mode control + truthful badge
- PHP: `OperationsSecurityScreen::render()` drops `deferralNote()` and keeps `modeCard()` after the checks;
  `modeCard()` is the sole nonce-/capability-gated mode form.
- JS: `SecurityCenter.js` `LaunchChecklist` loses its `action`/`dispatch` props and the entire mode-preview
  block; it reads `state.readiness?.blockingCount` for the badge. `securityCenterState.js` drops
  `selectedMode`/`productionPhrase`/`maintenanceConfirmed` from initial state, the `selectMode`/
  `setProductionPhrase`/`setMaintenanceConfirmed` reducer cases, `modeActionState()`, and demotes `MODES`
  from an export to a private in-range guard. Verified no other module imported the removed symbols.

### FR-004 — Record detail content
- New pure module `plugins/corex-config/src/admin/data/recordRows.js`: `recordRows(record, schemaFields)`
  → `[{ key, label, value }]`. `humanize()` mirrors `SubmissionsSource::labelFields()`; `display()` handles
  boolean/object/empty. `RecordDetail.js` consumes it and adds a "no readable fields" empty state.

### FR-005 — CorexSelect dropdowns
- `SettingsForm::select()` adds the static `data-corex-select` attribute. `NotificationsApp.js` swaps the
  native `<select>` for `CorexSelect` with a `SEVERITY_OPTIONS` list of translated labels.

### FR-006 / FR-007 — Toolbar count + admin rhythm
- `NotificationToolbar` uses the plain label for the visible node and keeps the counted phrasing on
  `meta.title`. `corex-admin-shell.css` adds zero-specificity `:where()` baseline margins for prose/headings/
  lists, an outer margin for a top-level `.corex-state`, and the `--notifications` nav-icon mask. `AdminPage`
  registers the `corex-notifications` page identity/labels; `render-admin.mjs` adds the notifications screen.
